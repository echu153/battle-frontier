## 0. 何を作って、何を作らないか

いまのv2の戦闘（[battle.js](../src/v2/lib/battle.js) の `runBattle`）は
**「最初から最後まで一気に回してログ配列を返す純関数」**で、プレイヤーの入力が入る余地がない。
ATBは「時間で溜まる → 入力待ちで止まる → 1行動だけ解決 → また溜まる」なので、
**一気に回せない**。＝**ループの外側だけを新しく作る**ことになる。

| 層 | 中身 | ATBで |
|---|---|---|
| ステータス組み立て | `createSide`（職業補正・パッシブ・エンチャント・ルーン） | **そのまま流用** |
| ダメージ・命中・クリ・軽減 | [combat.js](../src/v2/lib/combat.js) 全部 | **無改修** |
| 状態異常・出血毒・バフ | [ailments.js](../src/v2/lib/ailments.js) | **そのまま流用** |
| ログの文面 | [battleLog.js](../src/v2/lib/battleLog.js) | **そのまま流用** |
| **戦闘の進行** | `runBattle` のターンループ | **ここだけ新規（`src/v2/lib/atb.js`）** |

**ダメージ計算を二重に書かない**のが最重要（＝バランス調整の正が1か所に残る）。
ATB側が持つのは**ゲージ・入力待ち・時間の刻み**だけ。

### 既存コードに要る改修（案・小さい）

- `battle.js` の `takeAction(me, foe, rng, log)` → **第5引数でスキルを指定できるようにして export**
  （省略時はいままで通り `findSlot` で自動選択＝オート戦闘の挙動は1ミリも変わらない）
- `tickAil` / `tickRegen` を export（ATB側の刻みから呼ぶ）
- `runBattle` 本体・`combat.js`・スキルデータは**無改修**

## 1. ゲージ（案）

- ゲージは **0 → 100**。100 に届いた側が行動できる
- **毎秒の充填量 = 20 × R**（＝等速なら**5秒で1行動**）
- R ＝ **√(自分のAGI ÷ 相手のAGI)** を **0.5〜2.0** でクランプ

| AGI比（自分÷相手） | R | 1行動あたり |
|---|---|---|
| 0.25以下 | 0.5 | 10.0秒 |
| 0.5 | 0.71 | 7.1秒 |
| 1.0 | 1.0 | 5.0秒 |
| 2.0 | 1.41 | 3.5秒 |
| 4.0以上 | 2.0 | 2.5秒 |

- 平方根とクランプを噛ませるのは、オートの追加行動（`extraActionRate`＝AGI比10倍で+50%が上限）と
  **「AGIを伸ばすほど行動が増えるが頭打ちがある」という効き方を揃える**ため。
  ATBは差がそのまま行動回数になるので、素の比のままだと**AGI一強**になる
- 状態異常はATBで素直に化ける：**麻痺＝ゲージ停止**（1行動ぶん）・**鈍足＝R を0.8倍**
- **1挑戦は40〜80秒**を狙う（オートの10ターン相当＝10行動前後）

## 2. ターンという単位が消える問題（案）

いまは**ターン終了時**に出血・毒のtick／regen／バフの残ターン減らしをまとめてやっている。
ATBにはターン境界が無いので、代わりの刻みを決める必要がある。

**案A（推奨）：行動した本人を1ターンぶん進める**
自分が行動し終わったタイミングで、**自分の**出血・毒・regen をtickし、**自分に乗っているバフの残ターンを1減らす**。

- オートの1ターン＝両者1行動ずつ、なので**意味がほぼそのまま揃う**
- 既存の `tickAil` / `tickRegen` を**そのまま呼ぶだけ**で済む
- 速い編成は「バフが早く切れるが、その代わり行動も多い」＝釣り合う

案B：実時間5秒ごとに両者を刻む。→ **遅い編成ほど毒で損をする**（1行動あたりの被ダメが増える）ので却下。

## 3. スキルの発動率（proc）をどうするか（**最大の論点**・案）

v2のスキルは**オート前提**の作りになっている。

- `proc`（発動率）＝強い技ほど不発する（切り札75〜82%）
- `uses`（使用回数）＝1戦闘で3回まで
- 枠のポインタ順に自動で回る
- `priority`＝回復や防御を先に置くための先制値

このうち**プレイヤーが自分で選ぶATBと噛み合わないのは `proc` と `priority`**。
自分で選んだ技が25%で空振りするのは、オートなら「そういうもの」でもATBでは**ただのストレス**になる。

**案：ATB戦では proc を使わず、「必要ゲージ」に読み替える**

> 必要ゲージ ＝ **100 + (100 − proc) × 2**

| proc | 必要ゲージ | 等速での溜め |
|---|---|---|
| 100%（補助・防御態勢など） | 100 | 5.0秒 |
| 95%（通常技） | 110 | 5.5秒 |
| 85%（主力） | 130 | 6.5秒 |
| 75%（切り札） | 150 | 7.5秒 |
| 60%（敵の大技） | 180 | 9.0秒 |

- **新しい数値表を作らなくていい**（既存の proc から機械的に出る）＝スキルを増やしてもATB側は何もしなくてよい
- 「強い技ほど出しにくい」という設計意図が**そのまま残る**（不発ではなく待ち時間に変わるだけ）
- **溜めっぱなしで大技を狙う／小技を回転させる**という選択が生まれる＝ATBらしさの本体
- `uses` は据え置き（撃ち切ると通常攻撃だけになる）＝「10ターン相当で弾切れ」という
  ユニークボスのDPSチェックの前提を壊さない
- `priority` はATBでは意味を失うので**無視**する
- 通常攻撃は**必要ゲージ100で常に選べる**

⚠この案を採ると、ATB戦は**オート戦とは別バランス**になる（不発ぶんの期待値が消える）。
ユニークボスのHP式（[ユニークボス §3](v2-unique-boss-design.md)）は**ATB前提で測り直す**必要がある。

## 4. 画面（案）

```
┌────────────────────────────┐
│  サドニス            HP ██████████░░ 62%      │  ← 敵。ゲージも見せる
│                      ATB ███████░░░░░         │     （次に何が来るか読める）
├────────────────────────────┤
│  ログ（既存の V2LogLine をそのまま流す）        │
├────────────────────────────┤
│  えちゅ  HP ████████░░  MP ██████░░░░          │
│          ATB ██████████ 満タン！              │
│  ［強撃 130］［防御崩し 110］［防御態勢 100］   │  ← 足りない技はグレー
│  ［シールドアタック 110］［体当たり 110］       │
│  ［通常攻撃 100］          ［オート ON/OFF］    │
└────────────────────────────┘
```

- **ウェイト方式**（コマンドを開いているあいだ時間が止まる）を推奨。理由は§5
- 敵のゲージも出す。「あと2秒で大技が来るから今のうちに防御を積む」が成立する
- ログは既存の `buildBattleLog` の文面をそのまま1行ずつ流す（出撃と文体が揃う）

## 5. リアルタイム特有の穴と対策（技術・確定寄り）

| 穴 | 対策 |
|---|---|
| タブを裏に回すと `setInterval` が絞られる | dt は `Date.now()` の差分で取り、**1フレーム250msでクランプ**。裏に回すと実質止まる＝**損する側**なので悪用にならない |
| 回線・端末の速さで有利不利が出る | **ウェイト方式**にする（考えているあいだ止まる）。対人ではないので止めて困らない |
| 途中でリロードされた | **申告しない＝与ダメ0**。損するだけなので穴にならない |
| 与ダメの申告を改ざんされる | ユニークボスは**与ダメの蓄積がそのまま報酬**になるので、RPC側で**1挑戦あたりの上限（戦闘力から出す理論値）でクランプ**する。※これはATBだから増える穴ではなく、いまの出撃（`v2_sortie_settle`）も同じクライアント申告 |
| 操作が入るぶん時間あたりの試行回数が減る | ユニークボスの「1時間で想定130挑戦」が成立しなくなる。**ボスHPを測り直す**（§3の注記と同じ） |

## 6. オートとの併存（案）

ATB戦の画面にも**［オート］トグル**を置く。ONのあいだはゲージが満タンになった時点で
**既存の `findSlot` と同じ順番で自動的に撃つ**（＝いまのオート戦闘とほぼ同じ挙動になる）。

- ながら勢・操作したくない人を切らない
- **手動のほうが強い**（撃ち分け・大技の溜め）。ただし差は**1.2倍程度**に抑えて、
  オートが死に選択肢にならないようにする（＝周回の快適さを壊さない）

## 7. どこで使うか（案）

- **ユニークボス6体**（＝今回の導入目的・確定）
- 使わない：**出撃の周回**（1戦10〜20秒CDの周回に手動は乗らない）
- 将来の候補：アリーナの上位階・エリアボスの初回撃破・イベントボス

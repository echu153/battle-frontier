## 0. 何を作って、何を作らないか

いまのv2の戦闘（[battle.js](../src/v2/lib/battle.js) の `runBattle`）は
**「最初から最後まで一気に回してログ配列を返す純関数」**で、プレイヤーの入力が入る余地がない。
ATBは「時間で溜まる → 予約した行動が出る → また溜まる」なので、**一気に回せない**。
＝**ループの外側だけを新しく作る**ことになる。

| 層 | 中身 | ATBで |
|---|---|---|
| ステータス組み立て | `createSide`（職業補正・パッシブ・エンチャント・ルーン） | **そのまま流用** |
| ダメージ・命中・クリ・軽減 | [combat.js](../src/v2/lib/combat.js) 全部 | **無改修** |
| 状態異常・出血毒 | [ailments.js](../src/v2/lib/ailments.js) | **ターン→秒の読み替えだけ**（§2） |
| ログの文面 | [battleLog.js](../src/v2/lib/battleLog.js) | **そのまま流用** |
| **戦闘の進行** | `runBattle` のターンループ | **ここだけ新規（`src/v2/lib/atb.js`）** |

**ダメージ計算を二重に書かない**のが最重要（＝バランス調整の正が1か所に残る）。
ATB側が持つのは**ゲージ・予約・時間の刻み**だけ。

### 既存コードに要る改修（案・小さい）

- `battle.js` の `takeAction(me, foe, rng, log)` → **第5引数でスキルを指定できるようにして export**
  （省略時はいままで通り `findSlot` で自動選択＝オート戦闘の挙動は1ミリも変わらない）
- `tickAil` / `tickRegen` を export（ATB側の刻みから呼ぶ）
- **バフに残り時間を持たせる**（§2）。いまの `side.buffs` は `{ ステ: % }` だけなので、
  ATB用に `{ ステ: [{ pct, until }] }` を持つ形へ広げる。**オート戦闘側は無改修で通す**
- `runBattle` 本体・`combat.js`・スキルデータは**無改修**

## 1. ゲージと予約（確定＋案）

### 溜まり方（案）

- ゲージは **0 → 100** で1行動ぶん
- **毎秒の充填量 = 20 × R**（＝等速なら**5秒で1行動**）
- R ＝ **√(自分のAGI ÷ 相手のAGI)** を **0.5〜2.0** でクランプ

| AGI比（自分÷相手） | R | 1行動あたり |
|---|---|---|
| 0.25以下 | 0.5 | 10.0秒 |
| 0.5 | 0.71 | 7.1秒 |
| 1.0 | 1.0 | 5.0秒 |
| 2.0 | 1.41 | 3.5秒 |
| 4.0以上 | 2.0 | 2.5秒 |

- 平方根とクランプを噛ませるのは、オートの追加行動（`extraActionRate`＝AGI比10倍で+50%が上限）と
  **「AGIを伸ばすほど行動が増えるが頭打ちがある」という効き方を揃える**ため。
  ATBは差がそのまま行動回数になるので、素の比のままだと**AGI一強**になる
- **麻痺＝ゲージが5秒止まる**／**鈍足＝R が0.8倍**（＝状態異常がATBで素直に化ける）

### 予約（確定・アクティブ方式）

**時間は止まらない。** その代わり、**ゲージが溜まりきる前から次の行動を選んでおける**。

- 選んでおいた行動は、**必要ゲージに届いた瞬間に自動で発動**する（＝もたついて損をしない）
- 予約は**満タンになるまで何度でも変更できる**
- **予約していない状態で必要量に届いたら、ゲージは満タンのまま止まって待つ**（案）。
  押した瞬間に即発動する。＝**溜めた時間は無駄にならないが、殴られる時間は損する**
- 100を超える技（例：強撃130）を予約すると、**130に届くまで自動的に待ってから出る**。
  ＝「大技を予約して溜める」あいだは小技を撃てない**トレードオフ**が生まれる。これがATBの駆け引きの本体

## 2. バフ・デバフ・状態異常は「秒」で管理する（確定＋案）

⚠**いまのv2のバフは持続時間を持っていない**（`防御態勢 VIT+50%（重ねがけ可）` は戦闘が終わるまで永久に乗る）。
持続を持っているのは状態異常だけ。＝**バフに時間を持たせるのは新しい仕組み**になる。

### 換算（案）

**1ターン ＝ 等速の1行動 ＝ 5秒**として、いまのターン数をそのまま秒へ読み替える。

| 物 | いま | ATBでは |
|---|---|---|
| 出血（最後に付けてから） | 3ターン | **15秒** |
| 毒 | 4ターン | **20秒** |
| 鈍足 | 4ターン | **20秒** |
| 麻痺 | 1ターン | **5秒**（ゲージが止まる） |
| 回復阻害 | 3ターン | **15秒** |
| 継続回復（regen／mpRegen） | nターン | **n × 5秒** |
| **バフ・デバフ** | **無期限** | **20秒**（新規・一律。案） |

- 出血・毒のダメージは**5秒ごと**に入る（いまの「ターン終了時に1回」と同じ回数になる）
- **重ねがけ可のバフ**は、**掛け直すと残り時間がリセットされ、効果は加算**される。
  ＝いままで無限に積めた `防御態勢` は「**20秒のあいだに積める回数が上限**」になる（等速で3〜4回＝VIT+150〜200%）
- ＝**バフを撒く時間と殴る時間のトレードオフ**が生まれる。ATBと相性が良い

### 1挑戦が終わったら全部消える（確定）

勝っても負けても時間切れでも、**その挑戦で積んだバフ・デバフ・状態異常は全部リセット**。
次の挑戦は素の状態から始まる。

## 3. スキルの発動率（proc）→ 必要ゲージ（確定）

**ATB戦では `proc`（発動率）を使わない。** 自分で選んだ技が空振りするのはストレスなので、
**「不発する代わりに溜めが長い」**へ読み替える。

> 必要ゲージ ＝ **100 + (100 − proc) × 2**

| proc | 必要ゲージ | 等速での溜め |
|---|---|---|
| 100%（補助・防御態勢など） | 100 | 5.0秒 |
| 95%（通常技） | 110 | 5.5秒 |
| 85%（主力） | 130 | 6.5秒 |
| 75%（切り札） | 150 | 7.5秒 |
| 60%（敵の大技） | 180 | 9.0秒 |

- **新しい数値表を作らなくていい**（既存の proc から機械的に出る）＝スキルを増やしてもATB側は何もしなくてよい
- 「強い技ほど出しにくい」という設計意図が**そのまま残る**（不発ではなく待ち時間に変わるだけ）
- `uses`（使用回数3回）は**据え置き**。撃ち切ると通常攻撃だけになる＝「10行動前後で弾切れ」という
  ユニークボスのDPSチェックの前提を壊さない
- `priority`（先制値）はATBでは意味を失うので**無視**する
- 通常攻撃は**必要ゲージ100で常に選べる**
- 係数の 2 は案。1.5にすると大技が回りやすく、3にすると小技の回転が有利になる。**実測して決める**

⚠この読み替えにより、ATB戦は**オート戦とは別バランス**になる（不発ぶんの期待値が消えて**火力が上がる**）。
ユニークボスのHP式は**ATB前提で測り直す**（§7）。

## 4. 画面（案）

```
┌────────────────────────────────┐
│  サドニス                HP ██████████░░ 62%      │
│  ATB ███████░░░░░  ← 溜まりきると大技が来る        │
│  【デバフ】防御崩し ███░░ 8s ／ 毒 ██████░ 14s     │
├────────────────────────────────┤
│  ログ（既存の V2LogLine をそのまま流す）            │
├────────────────────────────────┤
│  えちゅ   HP ████████░░   MP ██████░░░░            │
│  ATB ████████░░ 82/130  ← 予約中：強撃             │
│  【バフ】防御態勢×2 ██████░ 13s ／ 気合い ██░ 4s   │
│  ［強撃 130］［防御崩し 110］［防御態勢 100］       │
│  ［シールドアタック 110］［体当たり 110］           │
│  ［通常攻撃 100］              ［オート ON/OFF］    │
└────────────────────────────────┘
```

- **予約中の技はボタンが光る**。ゲージのバーにも「82/130」と必要量を出す
- **バフ・デバフは自分と敵の両方**にバーで並べる（残り秒つき）。ここがこの戦闘の情報の要
- 敵のゲージも出す。「あと2秒で大技が来るから、いま防御態勢を予約する」が成立する
- ログは既存の `buildBattleLog` の文面をそのまま1行ずつ流す（出撃と文体が揃う）
- **1挑戦は40〜80秒**を狙う（オートの10ターン相当＝10行動前後）

## 5. リアルタイム特有の穴と対策（技術・確定寄り）

| 穴 | 対策 |
|---|---|
| タブを裏に回すと `setInterval` が絞られる | dt は `Date.now()` の差分で取り、**1フレーム250msでクランプ**。裏に回すと実質止まる＝**損する側**なので悪用にならない |
| 回線・端末の速さで有利不利が出る | **予約方式**がこれを消す（§1）。溜まりきる前に選んでおけるので、反応の速さを競わせない |
| 途中でリロードされた | **申告しない＝与ダメ0**。損するだけなので穴にならない |
| 与ダメの申告を改ざんされる | ユニークボスは**与ダメの蓄積がそのまま報酬**になるので、RPC側で**1挑戦あたりの上限（戦闘力から出す理論値）でクランプ**する。※これはATBだから増える穴ではなく、いまの出撃（`v2_sortie_settle`）も同じクライアント申告 |

## 6. オートとの併存（確定）

ATB戦の画面に**［オート］トグル**を置く。ONのあいだはゲージが必要量に届いた時点で
**既存の `findSlot` と同じ順番で自動的に撃つ**（＝いまのオート戦闘とほぼ同じ挙動になる）。

- ながら勢・操作したくない人を切らない（ユニークボスは1時間で何十回も殴るコンテンツ）
- **手動のほうが強い**（撃ち分け・大技の溜め・バフの掛け直し）。ただし差は**1.2倍程度**に抑えて、
  オートが死に選択肢にならないようにする

## 7. ユニークボス側で作り直しになるところ

[ユニークボス設計](v2-unique-boss-design.md) は**オート前提・バフ持ち越し前提**で数字を置いてあるので、
今回の確定でそのままでは通らない。**ATBを実装したあとに測り直す**。

| 向こうの記述 | 今回の確定との関係 |
|---|---|
| 「バフ／デバフは挑戦をまたいで蓄積」（確定事項） | **上書き。1挑戦で消える**（§2） |
| 「後半の挑戦ほど1回で削れる」＝バフ蓄積が前提 | **成立しなくなる**。1挑戦の与ダメは最初から最後までほぼ一定になる |
| ボスHP ＝ 96 × P × (P/2000)^0.22（想定130挑戦） | **測り直し**。バフ蓄積ぶんの伸びしろが消える一方、**不発が消えて火力が上がる**（§3）ので、上下どちらに振れるかは実測しないと分からない |
| 10ターンごとのDPSチェック | **秒に読み替える**（例：50秒ごと）。役割（削れない挑戦を早く畳む）は変わらない |

## 決めてほしいこと（残り）

1. **予約していないまま必要量に届いたとき**、ゲージは満タンで止まって待つ（§1の案）でよいか。
   ／ 溜まり続けて次の行動ぶんへ繰り越す（＝放置すると2回連続で動ける）
2. **バフの持続20秒**（＝等速で約4行動）でよいか。長い／短い
3. **状態異常も秒へ読み替える**（§2の表）でよいか。＝毒20秒・麻痺5秒など
4. 必要ゲージの係数 **2**（proc85%→130）でよいか。1.5＝大技が回りやすい／3＝小技が有利

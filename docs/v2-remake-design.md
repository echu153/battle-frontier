# バトルフロンティアⅡ（リメイク版）設計メモ

インフレしすぎた旧版を作り直すためのv2。**旧版のコードとデータには一切触れない**方針で、
同じリポジトリ・同じSupabaseプロジェクトの中に完全に分離して置く。

## 置き場所と切替

| 種別 | 旧版 | v2 |
|---|---|---|
| コード | `src/pages` `src/lib` | `src/v2/pages` `src/v2/lib` |
| ルート | `/game` ほか | `/v2` |
| テーブル | `profiles` ほか | `v2_` 接頭辞（`v2_profiles`） |
| SQL | 既存の各ファイル | `supabase_v2_core.sql` |

- 切替は街（`/game`）の☰メニュー →「🧪 リメイク版に切替[開発]」。PC/モバイル両方のメニューに設置。
- v2は **is_admin 限定**。非管理者が `/v2` を直接開いた場合は `reportDevAccess` で通知して `/game` へ戻す。
- キャラクターは旧版と別物。同じアカウントで両方遊べる。

## ステータス（あるけみすと準拠）

8種。正は [`src/v2/lib/stats.js`](../src/v2/lib/stats.js)。

| キー | 表示 | 意味 | 効果 | unit |
|---|---|---|---|---|
| `hp` | HP | 生命 | 0で戦闘不能 | 8 |
| `mp` | MP | 魔力 | スキル使用で消費 | 3 |
| `str` | STR | 腕力 | 通常攻撃と物理スキルの威力 | 1 |
| `dex` | DEX | 器用 | 命中率 | 1 |
| `agi` | AGI | 敏捷 | 行動順・行動回数・回避 | 1 |
| `int_stat` | INT | 知性 | 魔法攻撃の威力と魔法防御 | 1 |
| `vit` | VIT | 耐久 | 被ダメージ（回避・魔法防御にも軽微） | 1 |
| `luk` | LUK | 幸運 | クリティカル率・回避率 | 1 |

- `unit` = 抽選1回で上がる量。同時に「戦闘力1あたりの必要量」でもある（HP8＝戦闘力1）。
- 列名が `int_stat` なのは `int` がSQLの型名のため。JS側のキーも同じ `int_stat` に揃えてある（対応表を作らない＝ズレようがない）。
- **防御は独立ステータスを持たない**。あるけみすと同様、物理防御は VIT、魔法防御は INT と VIT から算出する
  （あるけみすとの式は 物理 `VIT×1.0〜0.5` / 魔法 `INT×1.0〜0.5 + VIT×0.15`）。実装は「ダメージと判定」を参照。
- **AGIの行動順・行動回数**は実装済み（「ダメージと判定」の項を参照）。ただし**戦闘ループ本体はまだ無い**ので、
  使うのは `combat.js` の純関数（`goesFirst` / `rollExtraAction`）だけ。

## 成長

- LVアップ1回につき **5回抽選**し、当たったステータスが `unit` だけ上がる。
- 8種すべて **均等 1/8**。当たりやすさを偏らせる「手相」は未採用（後から足せる）。
- どのステに当たっても戦闘力の上がり幅は同じ（1回＝戦闘力+1、1LV＝+5）。
- LV上限 **100**。上限到達後はEXPが入らない（転職待ち）。
- 必要EXPは **60** スタートで、**転職100回ごとに +10、100で打ち止め**
  （`min(100, 60 + floor(転職回数 / 100) × 10)`）。転職100回で70、200回で80、300回で90、400回以降は100。
  あるけみすとも転生数に応じて 70→80→90→100 と重くなる。`EXP_STEP_PER_JOBS` で変えられる。
- 初期ステータスは暫定値（HP40 / MP12 / 他5）＝戦闘力39スタート、LV100で534。
  あるけみすとの公表値が見つからなかったため決め打ち。`INITIAL_STATS` だけ直せば変えられる。

## 転職（あるけみすとの「転生」に相当）

- LV100でのみ実行できる。**LV1に戻り、ステータスは初期値へリセット**される。
- そこへ **「転職回数×100」戦闘力分**（100＝20LV分）を8種へランダムに振り分ける。
  前回の配分は引き継がず**毎回引き直し**（あるけみすとの「初期ステータスに転生回数×125を振り分ける」と同じ形）。
- 到達点は周回ごとに100ずつ上がる。

| 転職回数 | 転職直後の戦闘力 | LV100時 |
|---|---|---|
| 0 | 39 | 534 |
| 1 | 139 | 634 |
| 2 | 239 | 734 |
| 5 | 539 | 1034 |

- 転職では**転職先の職業を選ぶ**。選んだ職業の回数（`job_counts`）が1増え、上位職の条件はこれを見る。

## 職業

マスタの正は **DBの `v2_classes`**（`supabase_v2_core.sql` でシード）。クライアントはこの表を読んで表示するだけで、
JS側にマスタは持たない（二重定義を作らないため）。条件の判定はサーバー（`v2_change_job`）が行う。

- 開始時は **ノーブル**（転職先には選べない）
- 条件は2種類だけ。**「その初期職での転職回数」** と **「〈職業名〉の証」**
- 証の名前は全職業とも `職業名 + の証` で統一（`proofOf()` で導出できる）
- **証は転職のときに1個消費する**。そのため所持は個数で持つ（`proofs` = `{"侍の証":2}`）。
  同じ上位職にもう一度転職するには証をもう1個入手する必要がある
- 同じ職業に何度でも転職できる（上位職の条件を満たすには同じ初期職で3回必要）

| 区分 | 職業 | 条件 |
|---|---|---|
| 初期職 | 戦士 / 弓使い / 魔法使い / 僧侶 / 格闘家 / サモナー | なし |
| 上位職 | 侍・狂戦士 | 戦士で転職3回＋証 |
| | 狩人・暗殺者 | 弓使いで転職3回＋証 |
| | 元素使い・死霊使い | 魔法使いで転職3回＋証 |
| | 聖職者・異端審問官 | 僧侶で転職3回＋証 |
| | サイキッカー・体術師 | 格闘家で転職3回＋証 |
| | 精霊召喚士・式神使い | サモナーで転職3回＋証 |
| 複合上位職 | 魔法剣士 | 戦士3回＋魔法使い3回＋証 |
| | 魔銃士 | 弓使い3回＋魔法使い3回＋証 |
| | 聖騎士 | 僧侶3回＋戦士3回＋証 |
| | 賢者 | 魔法使い3回＋僧侶3回＋証 |
| | 武僧 | 格闘家3回＋僧侶3回＋証 |
| | ビーストレンジャー | サモナー3回＋弓使い3回＋証 |
| 特殊職 | ギャンブラー / 竜騎士 / ブリーダー | 証のみ |

- **職業の差はスキルだけ**（成長は職業に関係なく均等ランダム）。ステータス補正は付けていない。
  スキルは初期職6＋ノーブルのみ実装済みで、上位職・複合上位職・特殊職はまだ空。
- **証の入手手段もまだ無い**。確認用に `v2_debug_grant_proofs`（is_admin限定）で全種類を1個ずつ足せるようにしてある（押すたびに在庫が増える）。

## ダメージと判定

正は [`src/v2/lib/combat.js`](../src/v2/lib/combat.js)。あるけみすと準拠。

- 物理は **STR**、魔法は **INT** に**スキルの倍率**を掛ける
- 防御は**引き算ではなく％軽減**、しかも**上限がある**（物理は最大34%・魔法は最大50%）
  - 防御力＝物理は `VIT`、魔法は `INT + VIT×0.15`（防御専用ステータスは持たない）
  - あるけみすとの表記は `VIT×1.0〜0.5` / `INT×1.0〜0.5 + VIT×0.15`。主ステの係数は物理も魔法も
    同じ「1.0〜0.5」なので、**起点の1.0で揃える**（逓減は下の軽減率の式が担う）
  - ⚠ 2026-08-12まで物理だけ1.0・魔法だけ0.5と取り違えていて、**魔法防御が半分**になっていた
  - **魔法は軽減上限が高い（50%）うえに防御力も厚い**（同じステなら `INT+VIT×0.15` > `VIT`）ので、
    同じ倍率でも物理より通らない。**だから魔法スキルの倍率は物理より高く置く**
    （あるけみすとも同じ：魔法はINT×2.6・3.55、物理はSTR×2.2〜2.4）
  - 軽減率＝`上限 × 防御 / (防御 + 攻撃)`。防御をいくら積んでも上限に漸近するだけでダメージは0にならない
  - 旧版の「硬すぎて削れない／柔らかすぎて溶ける」の二極化を構造的に防ぐのが狙い
- クリティカルは**倍率×1.5＋1.5**かつ**相手の防御力÷1.5**（≒防御の1/3を無視）
  - **判定の順番もあるけみすと準拠**：先にクリティカルを決め、そのあと命中判定する。
    クリティカルの命中判定では **DEX×1.5 ＋ LUK÷3** をDEXとして扱う＝クリは通常より当たりやすい
  - **クリティカルするスキルとしないスキルがある**（あるけみすとも同じ。ゲーム内には表記されない）。
    スキル側の `noCrit` で指定する。逆に確定クリティカルは `sureCrit`（あるけみすとの破魔の一撃・刺閃に相当）
  - ⚠ `＋1.5` は**元の倍率によらない固定加算**なので、**倍率が低いほど伸び率が大きい**
    （0.57倍→約4.0倍／1.9倍→約2.4倍）。あるけみすとも「手数のあるスキルでクリティカルすると
    総係数への恩恵が大きい」と明記していて、低係数の刺閃や破魔の一撃が強いのはこれが理由。
    **v2では多段スキルを `noCrit` にして、そのぶん素の倍率を上げる**（そうしないと多段が壊れる）
- 命中は DEX と回避スコア（`AGI + VIT×0.1 + LUK×0.1`）の綱引き。40〜95%
- スキルは**発動率**を持ち、毎ターン抽選する（強い技ほど出にくくする）

### 行動順と行動回数（AGI）

あるけみすとは「AGIは行動順・行動回数・回避に影響」としか公表していないので、**ここは旧版（無印）準拠**。
ただし**上限を付け直している**。

- **行動順**：スキルの `priority` → AGI → 同値ならランダム。
  先制が付くのは**回復と防御バフだけ**（応急手当・身構える・防御態勢・ヒール・祈祷・プロテク）。
  攻撃バフ（気合い・精神統一・残心・駆け足）とMP回復は通常のAGI順
- **行動回数**：**相手よりAGIが高いときだけ**、確率で追加行動。
  AGI比 1倍で0%、**10倍で50%に到達してそこで打ち止め**（`extraActionRate`）

⚠ ここが旧版との一番大きな差。旧版は `(自SPD−敵SPD)/敵SPD×50` で**上限が無く**、
2倍差で50%・3倍差で75%…と伸び続けた。転生（転職）で差がつくほど一方的になる＝インフレの温床だった。

| 戦闘力 | AGI | 相手AGI 67に対する倍率 | v2 | 旧版 |
|---|---|---|---|---|
| 534（0転職） | 67 | 1.00倍 | 0% | 0% |
| 634（1転職） | 79 | 1.19倍 | 1.0% | 9.4% |
| 1034（5転職） | 129 | 1.94倍 | 5.2% | 46.8% |
| 2034（15転職） | 254 | 3.81倍 | 15.6% | 95.2% |
| 5334（48転職） | 669 | 9.99倍 | **50%（上限）** | 249.7% |

**この式はスケール不変**：同格どうしなら戦闘力がいくつでも殴り合いのテンポが変わらない。

| 戦闘力 | HP | STR | 倍率2.0のダメージ | 何発で倒れるか |
|---|---|---|---|---|
| 39（LV1） | 39 | 5 | 8 | 5 |
| 534（LV100） | 534 | 67 | 110 | 5 |
| 1034（転職5回・LV100） | 1034 | 129 | 214 | 5 |

命中・回避・クリティカル率の式はあるけみすとに公表が無いためBF独自。調整は `combat.js` の定数だけを触る。

### あるけみすとに準拠している範囲

| 項目 | あるけみすとの記載 | v2 |
|---|---|---|
| ステータス8種と役割 | HP/MP/STR/DEX/AGI/INT/VIT/LUK | 同じ |
| 戦闘力換算 | HPは1につき8・MPは1につき3 | 同じ |
| 物理・魔法の係数レンジ | 1.0〜0.66 ／ 1.0〜0.5 | 同じ（軽減上限34%／50%） |
| 物理防御力・魔法防御力 | VIT×1.0〜0.5 ／ INT×1.0〜0.5＋VIT×0.15 | VIT ／ INT＋VIT×0.15（係数は1.0で揃える） |
| クリティカル威力 | 係数×1.5＋1.5・防御÷1.5 | 同じ |
| クリティカルの命中補正 | DEX×1.5＋LUK÷3 | 同じ |
| クリティカルするスキル / しないスキル | あり（ゲーム内に表記なし） | 同じ（`noCrit`。v2では多段が対象） |
| 回復 | INT参照（神聖なる手 INT×1.5） | 同じ（初期職は低め） |
| **防御→係数の曲線** | **非公表** | `上限×防御/(防御+攻撃)`（BF独自） |
| **命中率・回避率の式** | **非公表** | DEX vs 回避スコア（BF独自） |
| **クリティカル発生率** | **マスクデータ** | LUK差（BF独自） |

出典は[基本情報](https://wikiwiki.jp/alchemist-p/%E5%9F%BA%E6%9C%AC%E6%83%85%E5%A0%B1)と[職業とスキル](https://wikiwiki.jp/alchemist-p/%E8%81%B7%E6%A5%AD%E3%81%A8%E3%82%B9%E3%82%AD%E3%83%AB)（有志のwiki）。
クリティカル関連はwiki側も「マスクデータのため要検証」と注記している。命中・回避・クリティカル率は
**元データが存在しない**ので準拠しようがなく、BF独自にせざるを得ない。

なお `上限×防御/(防御+攻撃)` は上限へ漸近するだけで到達しない（同格で物理17%・魔法20%軽減）。
あるけみすとの `(1.0〜0.66)` は端まで届く表記なので、ここは意図して差を残している（防御を効かせすぎないほうがインフレ対策になる）。

### 実測（LV100を3000体作って総当たり・主力スキルのみ・先攻有利を打ち消し済み）

| 職業 | 平均勝率 | 主力 | 期待ダメージ |
|---|---|---|---|
| 弓使い | 52.0% | 剛射 STR×1.9 | 89 |
| 魔法使い | 51.9% | サンダー INT×2.3 | 90 |
| 戦士 | 51.3% | 強撃 STR×1.9 | 89 |
| 格闘家 | 49.9% | 爆裂拳 STR×0.57×4（クリ無） | 93 |
| サモナー | 47.2% | 群れの号令 INT×0.75×3（クリ無） | 92 |
| 僧侶 | 45.8% | ライトニング INT×2.05 | 85 |

多段（クリ無）は期待ダメージが高く見えるが、クリティカルが乗らないぶんで釣り合っている。

転職差があるときの勝率（戦士どうし・0転職が相手）：

| 転職回数 | 戦闘力 | AGI | 追加行動率 | 勝率 |
|---|---|---|---|---|
| 0 | 534 | 67 | 0% | 49.5% |
| 1 | 634 | 79 | 1.0% | 91.3% |
| 2 | 734 | 92 | 2.1% | 98.8% |
| 5 | 1034 | 129 | 5.2% | 100% |

転職1回でほぼ勝てなくなる。**追加行動が原因ではなく、素のステータス差**（旧版の式なら5転職で追加行動47%が
さらに乗っていた）。対人を作るときは転職回数でマッチングを分けるか、補正を入れる必要がある。

決着は中央5〜10ターン、引き分けなし。ランダム成長のばらつきも小さく（STR 中央67・min41・max89）事故ビルドは出ない。
**この検証はバフと回復を使っていない**ので、支援の厚い僧侶・サモナーは戦闘ループを作ってから測り直すこと。

## スキル

正は [`src/v2/lib/skills.js`](../src/v2/lib/skills.js)。**名前は旧版から流用、倍率・発動率・消費MPはv2で新規**。
参照するステータスはv2の8種（物理=STR / 魔法=INT、副参照でAGI・VIT）。

- 倍率の置き方：あるけみすとは通常2.0〜2.6・大技4.0だが、**初期職は少し低め**にした
  （物理は通常1.0〜1.4／主力1.9まで、魔法は上限2.4まで・発動率75〜100%）。上位職に伸びしろを残すため
- **魔法の倍率は物理より高く置く**。魔法は軽減上限50%＋防御力も厚いので、同じ倍率では通らない。
  あるけみすとも同じ構図（魔法INT×2.6・3.55／物理STR×2.2〜2.4）
- **強い技ほど発動率を下げる**（物理は倍率1.8以上・魔法は2.0以上で発動率90%未満、
  倍率1.2以下は90%以上）。テストで固定している
- **多段スキルは `noCrit`（クリティカルしない）にする**。クリの固定加算はどの倍率にも同じだけ乗るので、
  多段ほど恩恵が大きくなり調整不能になる。クリを切ったぶん素の倍率を上げて釣り合わせる。
  「多段は必ず noCrit」「合計倍率が単発の主力を超えない」「職業ごとの主力の実質倍率が2割以上開かない」を
  テストで固定している
  （※2026-08-12に爆裂拳 0.7×4＝合計2.8 で格闘家が全職に76〜98%勝つ状態を作った。これらはその再発検出）

**実質倍率＝(倍率＋副参照)×多段数×発動率**。ただし物理と魔法は防御の効きが違うので直接は比べられない。
最終的な確認は同格の期待ダメージと勝率シミュレーションで行う。

- **回復はHP回復もMP回復もINTを参照する**（あるけみすと準拠。神聖なる手＝INT×1.5）。
  最大HP/MPの％では計算しない＝HPを積むほど回復量まで伸びる歪みを作らないため。
  **回復系の発動率は80%**（あるけみすとの回復も75〜80%が中心）
- 実装済みは**ノーブル＋初期職6の計7職・各5個**
- **状態異常（毒・出血・麻痺）はまだ入れていない**。設計してから足す
- 職業ごとのスキルの割り当ては旧版の実装（`Game.jsx` の `executeSkill`）から拾った。
  正はDBの `skills` テーブルなので、ズレがあれば直す

同格（戦闘力534どうし・HP534）に対する1ターンの期待ダメージ：

| 職業 | 主力 | 期待 | 補助 |

| ノーブル | はたく STR×1.1 | 57 | 応急手当・身構える・気合い |
| 戦士 | 強撃 STR×1.9 | 89 | 防御態勢（VIT+30%） |
| 弓使い | 剛射 STR×1.9 | 89 | 駆け足（AGI+30%）・狙撃は必中 |
| 魔法使い | サンダー INT×2.3 | 90 | 精神統一（INT+30%） |

| 格闘家 | 爆裂拳 STR×0.57×4（クリ無） | 93 | 残心（DEX・AGI+20%）・鉄拳 STR×1.9 |
| サモナー | 群れの号令 INT×0.75×3（クリ無） | 92 | 小悪魔召喚 INT×1.95・魔力供給 INT×0.3×4T（期待64MP・消費0） |

回復（INT67・HP534・MP200のとき）：応急手当 INT×1.0＝66／ヒール INT×1.4＝93／祈祷 INT×0.5×4T＝33ずつ／魔力供給 INT×0.3×4T＝20ずつ。
**INT参照なので物理職の自己回復は伸びない**（STRに寄せるほど応急手当が薄くなる）＝ステの振り方が回復量にも効く。

## サーバー権威

旧版はクライアントからステータスを書き換えられる穴を抱えたままなので、v2は最初から
**すべての更新をRPC経由**にする。

- `v2_profiles` にはSELECTポリシーしか無い＝クライアントから直接INSERT/UPDATEできない。
- `v2_apply_exp(uuid, int)` … EXP付与とLVアップ抽選の本体。SECURITY DEFINER。
  **PUBLIC/anon/authenticated からREVOKE済み**（＝直接呼べない）。EXP源となるRPCの中からだけ呼ぶ。
- `v2_create_character(text)` … キャラ作成。authenticated のみ。
- `v2_change_job(text)` … 転職。LV100の判定・転職条件（回数と証）・リセット・振り分けをすべてサーバーで行う。authenticated のみ。
- `v2_debug_gain_exp(int)` … 成長確認用にEXPを自分へ入れる。**is_admin限定・開発用**。
  本番のEXP源（戦闘など）を作ったら、そちらから `v2_apply_exp` を呼び、このRPCは公開しない。

抽選ロジックはJS（表示・シミュレーション用）とSQL（正）の2箇所にある。
**片方だけ直すと表示と実値がズレる**ため、`STAT_KEYS` の並びと `unit`・定数は必ず同時に直すこと。
並び順は `src/v2/lib/stats.test.js` が固定している。

v2のSQLは `supabase_v2_core.sql` **1ファイルにまとめる**（分割しない）。全体が冪等なので、
仕様を足すたびに全文を流し直す運用にする。旧版で起きた「後から流したSQLが前の定義を巻き戻す」事故を避けるため。

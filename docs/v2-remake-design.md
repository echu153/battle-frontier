# バトルフロンティアⅡ（リメイク版）設計メモ

インフレしすぎた旧版を作り直すためのv2。**旧版のコードとデータには一切触れない**方針で、
同じリポジトリ・同じSupabaseプロジェクトの中に完全に分離して置く。

## 置き場所と切替

| 種別 | 旧版 | v2 |
|---|---|---|
| コード | `src/pages` `src/lib` | `src/v2/pages` `src/v2/lib` |
| ルート | `/game` ほか | `/v2` |
| テーブル | `profiles` ほか | `v2_` 接頭辞（`v2_profiles`） |
| SQL | 既存の各ファイル | `supabase_v2_core.sql` |

- 切替は街（`/game`）の☰メニュー →「🧪 リメイク版に切替[開発]」。PC/モバイル両方のメニューに設置。
- v2は **is_admin 限定**。非管理者が `/v2` を直接開いた場合は `reportDevAccess` で通知して `/game` へ戻す。
- キャラクターは旧版と別物。同じアカウントで両方遊べる。

## ステータス（あるけみすと準拠）

8種。正は [`src/v2/lib/stats.js`](../src/v2/lib/stats.js)。

| キー | 表示 | 意味 | 効果 | unit |
|---|---|---|---|---|
| `hp` | HP | 生命 | 0で戦闘不能 | 8 |
| `mp` | MP | 魔力 | スキル使用で消費 | 3 |
| `str` | STR | 腕力 | 通常攻撃と物理スキルの威力 | 1 |
| `dex` | DEX | 器用 | 命中率 | 1 |
| `agi` | AGI | 敏捷 | 行動順・行動回数・回避 | 1 |
| `int_stat` | INT | 知性 | 魔法攻撃の威力と魔法防御 | 1 |
| `vit` | VIT | 耐久 | 被ダメージ（回避・魔法防御にも軽微） | 1 |
| `luk` | LUK | 幸運 | クリティカル率・回避率 | 1 |

- `unit` = 抽選1回で上がる量。同時に「戦闘力1あたりの必要量」でもある（HP8＝戦闘力1）。
- 列名が `int_stat` なのは `int` がSQLの型名のため。JS側のキーも同じ `int_stat` に揃えてある（対応表を作らない＝ズレようがない）。
- **防御は独立ステータスを持たない**。あるけみすと同様、物理防御は VIT、魔法防御は INT と VIT から算出する
  （あるけみすとの式は 物理 `VIT×1.0〜0.5` / 魔法 `INT×1.0〜0.5 + VIT×0.15`）。戦闘を実装するときに確定させる。

## 成長

- LVアップ1回につき **5回抽選**し、当たったステータスが `unit` だけ上がる。
- 8種すべて **均等 1/8**。当たりやすさを偏らせる「手相」は未採用（後から足せる）。
- どのステに当たっても戦闘力の上がり幅は同じ（1回＝戦闘力+1、1LV＝+5）。
- LV上限 **100**、必要EXP **60**（固定）。上限到達後はEXPが入らない。
- **転生は未実装**。あるけみすとではLV100で転生し「転生回数×125」戦闘力分が初期ステに配られる。
- 初期ステータスは暫定値（HP40 / MP12 / 他5）＝戦闘力39スタート、LV100で534。
  あるけみすとの公表値が見つからなかったため決め打ち。`INITIAL_STATS` だけ直せば変えられる。

## サーバー権威

旧版はクライアントからステータスを書き換えられる穴を抱えたままなので、v2は最初から
**すべての更新をRPC経由**にする。

- `v2_profiles` にはSELECTポリシーしか無い＝クライアントから直接INSERT/UPDATEできない。
- `v2_apply_exp(uuid, int)` … EXP付与とLVアップ抽選の本体。SECURITY DEFINER。
  **PUBLIC/anon/authenticated からREVOKE済み**（＝直接呼べない）。EXP源となるRPCの中からだけ呼ぶ。
- `v2_create_character(text)` … キャラ作成。authenticated のみ。
- `v2_debug_gain_exp(int)` … 成長確認用にEXPを自分へ入れる。**is_admin限定・開発用**。
  本番のEXP源（戦闘など）を作ったら、そちらから `v2_apply_exp` を呼び、このRPCは公開しない。

抽選ロジックはJS（表示・シミュレーション用）とSQL（正）の2箇所にある。
**片方だけ直すと表示と実値がズレる**ため、`STAT_KEYS` の並びと `unit`・定数は必ず同時に直すこと。
並び順は `src/v2/lib/stats.test.js` が固定している。

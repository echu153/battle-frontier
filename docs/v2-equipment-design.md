⚠**このファイルはまだ策定中。「確定」と書いたものだけが決まっている。**
数値は敵とPvEコンテンツができるまで**すべて仮**（いまのバランス検証は同格どうしの
シミュレーションだけで、「この防具でこの敵に通用するか」は判定できない）。

## あるけみすとの装備（[wiki](https://wikiwiki.jp/alchemist-p/%E8%A3%85%E5%82%99) で確認・2026-08-14）

v2はこれを土台にする。

| | あるけみすと |
|---|---|
| 補正 | **固定値**。「戦闘力の数値だけ各ステータスが上昇する」＝**装備は「戦闘力」を1つ持ち、それが各ステへ配分される**。配分は**マスクデータ**で確認できない |
| 部位 | 武器 / 頭具 / 防具 / 足具 / アクセサリー の5種 |
| 合成 | **同じ強化値の装備3つ＋10マー** → 失敗（**消失**）／成功 +1／大成功 +2／超大成功 +3 |
| | **戦闘力の高い装備ほど失敗しやすく、極端な結果も出やすい** |
| | 「霊魂の宝石」で結果を成功に固定できる。+4以上で宝石なしだと警告画面 |
| 強化値 | 表データ上は **+12** まで確認（上限は不明） |
| 入手 | 探索・闘技場でまれにドロップ／市場で購入 |

★**固定値でも周回に置いていかれないのは、合成で装備そのものが育つから。**
転職でステータスが上がっても、装備を合成で伸ばせば追いつける。
しかも3個合成は装備を指数的に食うので、**ドロップした装備の吸収弁**として働く
＝インフレ抑制になっていて、v2の方針とも合う。

## 確定していること

- **補正は固定値**（あるけみすと式）。％ではない
- **強化は「同じ強化値の装備3個を合成」**（あるけみすと式）
- **枠は8つ**（あるけみすとの5種より多い）
  | 区分 | 枠 |
  |---|---|
  | 武器 | 右手 / 左手 |
  | 防具 | 頭 / 鎧 / 腕 / 足 |
  | アクセサリ | 2枠 |
- **装備で伸びるステータスは STR / DEX / AGI / VIT / INT の5種だけ**
  - **HP・MP・LUKは装備に載せない**。HPは全ステ中もっとも強く、MPは戦闘中まず尽きないので、
    載せると「HP装備一択・MP装備は死に枠」になる
  - MPは天空闘技場（HP/MPが回復しない連戦・実装予定）と、消費MPが増えるほど威力が上がる
    スキル（同じく予定）で意味を持たせる
- **ステータスの土台はあるけみすと式のまま**。VIT/DEXが攻撃ステより効率が悪いのは
  仕様として受け入れ、**装備の数値でバランスを取る**

## 制約（実測から出ている数字）

**VITとDEXには天井がある。** 数値を盛れば盛るだけ効く、にはならない。

| 主ステに対する倍率 | 1倍 | 2倍 | **3倍** | 5倍 | 10倍 |
|---|---|---|---|---|---|
| DEX：通るダメージ | ×1.000 | ×1.112 | **×1.152** | ×1.189 | ×1.220 |
| VIT：物理の被ダメージ | 83.0% | 77.3% | **74.5%** | 71.7% | 69.1% |

→ **有効レンジはどちらも「主ステの3倍」あたりまで。そこから先は捨て値。**
装備を全部盛って主ステの3倍を超える設計にしないこと。

もうひとつ、**防具にVIT/DEXだけを載せると誰も着けない**（同じ数値ならSTR/INTのほうが
16〜28倍効率がいい）。防具にもSTR/INTを載せるか、数値以外の価値を付ける。

## 確定：ランク・強化・武器種

### ランクと基礎戦闘力

**F・E・D・C・B・A・S の7段階**（あるけみすとと同じ段数）。基礎戦闘力は **F=10 から S=70 まで10ずつ**。
SS(80)・SSS(90)まで設計してあるが、**最初の実装には入れない**。

### 強化

**1段階ごとに一律 ×1.5**（あるけみすとは1.5〜1.9とランクで変えていたが、v2は揃える）。

⚠この差は意識しておくこと。あるけみすとは**低ランクほど倍率が高く**、強化するとランク差が縮まる
設計だった。v2は一律なので**ランク差（S÷F＝7倍）は永久に縮まらない**。
代わりに、低ランクは強化値で追い越す（F+12＝1297 が A+5＝456 を超える）。

### 装備の一覧（F〜S）

**最初の実装は F〜S の7段階まで**（あるけみすとと同じ段数）。SS・SSSは名前だけ用意して後で足す。

| | 内訳 | 本数 |
|---|---|---|
| 武器 | 10種 × 7ランク | 70 |
| 防具 | 3系統（重装・軽装・魔装）× 4部位（頭・鎧・腕・足）× 7ランク | 84 |
| アクセサリ | 4種 × 7ランク | 28 |
| | | **182本** |

**両手武器は枠を2つ使うので戦闘力2.2倍**（二刀流との選択になる）。盾は左手専用。
**鎧だけ戦闘力1.3倍**（防具の中心）。**アクセは0.8倍**で、枠は2つ・同じ種類を2つ着けてもよい。

防具の配分は「**系統**が主ステ55%、**部位**が副ステ30%、系統の第3ステ15%」で決める
（系統：重装=VIT／軽装=AGI／魔装=INT ・ 部位：頭=DEX／鎧=VIT／足=AGI／腕=系統の攻撃ステ）。
主と副が重なる組（重装の鎧・軽装の足・魔装の腕）は合算されて**その系統の一番尖った部位**になる。

★**どの系統もSTRかINTを含む**のが要点。VIT/DEXだけの防具は、同じ数値なら攻撃ステのほうが
16〜28倍効率がいいので誰も着けない（「制約」の項を参照）。

⚠**ネックレス（バランス）は名目上5ステ均等だが実際には一番弱い**。同じ理由で半分が薄まる。

★命名の決まりごと：

**1語の武器名と、修飾つきの名前を混ぜる。** どちらかに寄せると単調になる（両方やって失敗した）。
目安は下位ほど1語・上位ほど修飾つきで、**修飾は1ランクに2〜4本**。

| ランク | 混ぜ方 | 例 |
|---|---|---|
| F〜D | ほぼ1語。**弱さは名前の素っ気なさで出す** | ソード／ナイフ／竹槍／グローブ |
| C〜B | 実在の武器名が主、情景の修飾を2〜3本 | バルディッシュ／月影の短剣／翡翠のランス |
| A | ミスリル系＋修飾。ミスリルは3本まで | ミスリルソード／霧隠れのダガー／業火の戦斧 |
| S | 漢語の造語が主、固有名を1〜2本だけ | 蒼氷剣／処刑斧ギロチナ／金剛籠手 |

消すのは**しょうもない修飾**だけ：

- ⚠**状態・質の説明**（なまくらの剣／弦の緩んだ弓／継ぎ接ぎの盾）＝冗長なだけで何も足さない
- ⚠**平凡な形容＋一般名詞**（疾風の長弓／賢者の長杖）＝ただの弓・ただの杖に見える
- ⚠**漢語一発**（破天／万象）＝武器種の語を付けて「万象杖」にする
- ⚠**同じ系統を1ランクに3本以上並べない**（枯れ枝の杖／板切れの盾／丸太の大剣）

残すのは：それ自体が武器の名前になっている語（カイトシールド／バルディッシュ／グリモア）、
像のある修飾（月影／翡翠／霧隠れ／業火）、漢語の造語（蒼氷剣／覇滅斧）、固有名を少しだけ。

**どのランクでも名前だけで武器種が分かること**（「板切れ」「枯れ枝」は読めない）。

| ランク | F | E | D | C | B | A | S |

# 以下は案（未確定）

## 案① 装備は「戦闘力」を1つ持ち、決まった配分で5ステへ散らす（配分は表示する）

あるけみすとと同じ形。v2の戦闘力換算（`Σ stat / unit`）とそのまま噛み合う。

```
鉄の剣  戦闘力26（D）  → STR 20 / DEX 6
革の鎧  戦闘力26（D）  → VIT 16 / AGI 6 / STR 4
```

- **1つの数字（戦闘力）で装備どうしを比べられる**のが利点。ランクもドロップ設定もこれで決まる
- 配分を変えるだけで「攻撃寄りの鎧」「守り寄りの剣」が作れる
- **配分は表示する**（確定）。あるけみすとはマスクデータにしているが、v2はスキルセットの
  想定利用MPなど数値を見て組むゲームなので隠す理由がない
- **どの枠にもどのステも載りうる**ことにして、枠ごとにステを縛らない
  （防具＝VIT/DEXだけ、にすると上の理由で誰も着けない）。武器は攻撃寄り・防具は守り寄り、
  という「傾向」は付けるが固定はしない

## 案③ 合成の確率

あるけみすとは「戦闘力の高い装備ほど失敗しやすく、極端な結果も出やすい」。同じ形にする。
**Fは失敗0%＝いくらでも合成できる**（入手も一番しやすい枠なので、下位を大量に育てる道を残す）。

| ランク | 成功(+1) | 大成功(+2) | 超大成功(+3) | 失敗（消失） |
|---|---|---|---|---|
| F | 85% | 12% | 3% | **0%** |
| E | 82% | 13% | 3% | 2% |
| D | 78% | 14% | 4% | 4% |
| C | 74% | 15% | 5% | 6% |
| B | 69% | 16% | 6% | 9% |
| A | 64% | 17% | 7% | 12% |
| S | 58% | 18% | 9% | 15% |

- 3個入れて1個出るので、**1段階上げるのに実質2.2〜2.4個**（大成功ぶんの割引込み）
- 上限は **+12**（あるけみすとの確認値に合わせる）。ただし現実に触れる帯は+2〜+4
- **失敗保護のアイテム**（あるけみすとの「霊魂の宝石」に相当）は入れる。名前は未定
- ⚠**+4以上で保護なしのときは確認を1段挟む**（あるけみすとと同じ）。旧版で
  「連打で溶かした」事故を作らないため

## 案④ 特殊能力はパッシブの語彙を使い回す

すでに `skills.js` の `PASSIVE_EFFECT_KEYS` に16種の効果が定義してあり、`battle.js` の
`collectPassives` / `liveStats` が解釈する。**装備の特殊能力も同じ形（`passive:{...}`）で書けば、
戦闘ループ側の実装が要らない。**

例：`{ hitBonus:3 }` 命中+3% ／ `{ dodgeCut:{ pct:5, cut:20 } }` 5%で20%カット ／
`{ healBonus:10 }` 回復量+10%

- ⚠パッシブスキルと足し算になるので、**装備側は一段控えめ**にする（パッシブが+5%なら装備は+3%）
- A・S級だけに1つ載せる、くらいの頻度が無難

## 案⑤ 個体差（同じ装備でも数値がランダムに違う）は入れない

強化は3個合成で入るので、そのうえ個体差まで入れると比較が難しくなる。
旧版のランダム加工は事故（[marketplace-bound-craft-incident]）も起こしている。

## 案⑥ DBとサーバー権威

⚠**装備を入れる時点で、いまクライアント側にある戦闘計算の扱いを決める必要がある。**
装備値をクライアントが持つと、旧版と同じ「ブラウザから書き換えられる」穴になる。

| テーブル | 中身 |
|---|---|
| `v2_equipment` | マスタ。`id / name / slot / rank / power / stats jsonb / passive jsonb / two_handed` |
| `v2_inventory` | 所持。`id / player_id / equip_id / plus`（★強化値は個体ごとなのでここ） |
| `v2_profiles.equipped` | 装着中。`{"right":123, "head":45, ...}` の jsonb（`v2_inventory.id` を指す） |

- RPC：`v2_equip(slot, inventory_id)` / `v2_unequip(slot)` / `v2_fuse(id1, id2, id3, use_gem)`
  - **枠の種類チェック・強化値が3つとも同じかの確認・抽選はすべてサーバー**
  - 合成は消失を伴うので、**必ずトランザクション**で（旧版の補填SQLを書く羽目になった事故がある）
- 両手武器（`two_handed`）は右手に着けると左手を塞ぐ
- 戦闘結果をサーバーで計算するかは別途決める（当面クライアントのままにするなら、
  少なくとも装備の**所持・装着・合成**はサーバー権威にしておく）

## 案⑦ 入手経路

敵がまだ無いので方針だけ。

- 基本は**敵のドロップ**（エリア／ボスごとにテーブル）
- 店は初級装備だけ
- 分解は入れない（合成が装備を食うので、素材化まで作ると経路が増えすぎる）
- ⚠**市場（プレイヤー間取引）はあるけみすとにはあるが、v2では後回し**。
  旧版で取引所がらみの事故が複数あった

## 決まっていない・保留

- 各ランクの具体的な数値（**敵ができるまで仮**）
- 装備に状態異常の耐性枠を作るか ← **作るなら状態異常の設計が先**。後付けだと装備を作り直すことになる
- 失敗保護アイテムの名前と入手経路
- 見た目（アイコン・画像）をどうするか

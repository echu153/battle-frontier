# バトルフロンティアⅡ 装備 設計メモ（策定中）

⚠**このファイルはまだ策定中。「確定」と書いたものだけが決まっている。**
数値は敵とPvEコンテンツができるまで**すべて仮**（いまのバランス検証は同格どうしの
シミュレーションだけで、「この防具でこの敵に通用するか」は判定できない）。

前提は [v2-remake-design.md](v2-remake-design.md) の「ステータスを伸ばす価値」を参照。

## 確定していること

- **枠は8つ**
  | 区分 | 枠 |
  |---|---|
  | 武器 | 右手 / 左手 |
  | 防具 | 頭 / 鎧 / 腕 / 足 |
  | アクセサリ | 2枠 |
- **装備で伸びるステータスは STR / DEX / AGI / VIT / INT の5種だけ**
  - **HP・MP・LUKは装備に載せない**。HPは全ステ中もっとも強く、MPは戦闘中まず尽きないので、
    載せると「HP装備一択・MP装備は死に枠」になる
  - MPは天空闘技場（HP/MPが回復しない連戦・実装予定）と、消費MPが増えるほど威力が上がる
    スキル（同じく予定）で意味を持たせる
- **ステータスの土台はあるけみすと式のまま**。VIT/DEXが攻撃ステより効率が悪いのは
  仕様として受け入れ、**装備の数値でバランスを取る**

## 制約（実測から出ている数字）

**VITとDEXには天井がある。** 数値を盛れば盛るだけ効く、にはならない。

| 主ステに対する倍率 | 1倍 | 2倍 | **3倍** | 5倍 | 10倍 |
|---|---|---|---|---|---|
| DEX：通るダメージ | ×1.000 | ×1.112 | **×1.152** | ×1.189 | ×1.220 |
| VIT：物理の被ダメージ | 83.0% | 77.3% | **74.5%** | 71.7% | 69.1% |

→ **有効レンジはどちらも「主ステの3倍」あたりまで。そこから先は捨て値。**
装備を全部盛って主ステの3倍を超える設計にしないこと。

もうひとつ、**防具にVIT/DEXだけを載せると誰も着けない**（同じ数値ならSTR/INTのほうが
16〜28倍効率がいい）。防具にもSTR/INTを載せるか、数値以外の価値を付ける。

# 以下は案（未確定）

## 案① 補正は「固定値」ではなく「％」にする ★これが一番大きい論点

v2の最大のテーマは「インフレしすぎた旧版を作り直す」こと。**装備を固定値にすると、
そこがインフレの入口になる。**

| 転職回数 | 素のステ | 固定値装備（+20×8枠） | 倍率 | ％装備（+25%×8枠） | 倍率 |
|---|---|---|---|---|---|
| 0 | 67 | 227 | ×3.39 | 201 | ×3.00 |
| 1 | 79 | 239 | ×3.03 | 237 | ×3.00 |
| 5 | 129 | 289 | ×2.24 | 387 | ×3.00 |
| 15 | 254 | 414 | ×1.63 | 762 | ×3.00 |
| 48 | 667 | 827 | **×1.24** | 2001 | ×3.00 |

固定値だと**転職を重ねるほど装備が無意味になり**、結局「もっと強い装備」を出し続けるしかない
＝旧版と同じ道になる。％なら周回がいくつでも同じ意味を持つ。

v2はダメージ式・職業補正・パッシブがすべて％／スケール不変で作ってあるので、**装備だけ固定値にすると
そこだけ設計が食い違う**。戦闘ループ側も `buffs` がすでに％の足し算なので、実装もそのまま乗る。

- ⚠デメリット：「STR+10の剣」より直感的でない。低LV帯は素ステが小さいので恩恵が薄い
- 折衷（固定値＋％の両方を持たせる）も可能だが、表示も計算も複雑になるので推さない

## 案② 1枠あたりの補正量とランク

「8枠を1ステに全部寄せて主ステの3倍（＝+200%）」を上限に置くと、**1枠あたり最大+25%**。

| ランク | 1枠の補正合計 | 例 |
|---|---|---|
| C | +6% | STR+6% |
| B | +10% | STR+7% / VIT+3% |
| A | +15% | STR+10% / DEX+5% |
| S | +20% | STR+12% / DEX+5% / AGI+3% |
| SS | +25% | STR+15% / DEX+6% / AGI+4% ＋ 特殊能力1つ |

- 実際には枠ごとに載るステが違うので、1ステあたりは **+60〜100%** に落ち着く見込み
- **どの枠にもどのステも載りうる**ことにして、枠ごとにステを縛らない
  （防具＝VIT/DEXだけ、にすると上の理由で誰も着けない）
- 武器は攻撃寄り・防具は守り寄り、という「傾向」は付けるが固定はしない

## 案③ 特殊能力はパッシブの語彙を使い回す

すでに `skills.js` の `PASSIVE_EFFECT_KEYS` に16種の効果が定義してあり、`battle.js` の
`collectPassives` / `liveStats` が解釈する。**装備の特殊能力も同じ形（`passive:{...}`）で書けば、
戦闘ループ側の実装が要らない。**

例：`{ hitBonus:3 }` 命中+3% ／ `{ dodgeCut:{ pct:5, cut:20 } }` 5%で20%カット ／
`{ healBonus:10 }` 回復量+10%

- ⚠パッシブスキルと足し算になるので、**装備側は一段控えめ**にする（パッシブが+5%なら装備は+3%）
- SS級だけに1つ載せる、くらいの頻度が無難

## 案④ 強化・進化は入れない（少なくとも最初は）

旧版は強化+10・進化5段階＋真化まであって、インフレの主因のひとつだった。
v2では**まず入れずに出す**。足りなければ後から足せるが、外すのは難しい。

- 同じ理由で **個体差（同じ装備でも数値がランダムに違う）も入れない**。
  旧版のランダム加工は事故（[marketplace-bound-craft-incident]）も起こしている

## 案⑤ DBとサーバー権威

⚠**装備を入れる時点で、いまクライアント側にある戦闘計算の扱いを決める必要がある。**
装備値をクライアントが持つと、旧版と同じ「ブラウザから書き換えられる」穴になる。

| テーブル | 中身 |
|---|---|
| `v2_equipment` | マスタ。`id / name / slot / rank / stats jsonb / passive jsonb / two_handed` |
| `v2_inventory` | 所持。`player_id / equip_id / obtained_at` |
| `v2_profiles.equipped` | 装着中。`{"right":123, "head":45, ...}` の jsonb |

- RPC：`v2_equip(slot, inventory_id)` / `v2_unequip(slot)`。**枠の種類チェックはサーバー**
- 両手武器（`two_handed`）は右手に着けると左手を塞ぐ
- 戦闘結果をサーバーで計算するかは別途決める（当面クライアントのままにするなら、
  少なくとも装備の**所持と装着**はサーバー権威にしておく）

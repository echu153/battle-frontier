# バトルフロンティアⅡ — ペットシステム 設計メモ

作成 2026-08-27。**確定**＝ユーザー承認済み／**案**＝こちらの提案で未承認。
数値は原則すべて案。v2の慣例どおり、確定前に tools のスクリプトで逆算する。

---

## 1. 何をするものか（確定）

ペットを1体持ち、**ゲーム内の遊びと現実の行動**で育てる。
育ったペットのステータスが、主人公のステータスに実数で加算される。

ステータスは6種。v2本編の8種から HP・MP を除いたものと完全に一致するため、
受け皿を新設せず `str / dex / agi / int_stat / vit / luk` にそのまま乗る。
（[src/v2/lib/stats.js](../src/v2/lib/stats.js) の `STAT_KEYS`）

---

## 2. コンテンツとステータスの対応（確定）

| ステ | コンテンツ | 何を測るか |
|---|---|---|
| STR | リアルの運動量 | 歩数・移動距離 |
| INT | 学力（漢字検定3級〜1級） | 正答数 |
| VIT | 積み上げ耐久（ミニゲーム） | 崩れるまでに乗せた個数 |
| DEX | 神経衰弱 | めくった手数の少なさ |
| AGI | 神経衰弱 | クリアタイム |
| LUK | コイントス | 連続的中 |

軸の切り方は「量＝STR／知＝INT／継続＝VIT／正確さ＝DEX／速さ＝AGI／運＝LUK」。
**神経衰弱だけ1プレイでDEXとAGIの両方に入る**（速いだけ・正確なだけでは片方しか埋まらない）。

積み上げ耐久はDEXと操作精度で被りやすいので、
1個ごとの操作は易しく・**乗せた個数が増えるほど揺れを大きく**して、
「精度」ではなく「どこまで持ちこたえたか」がスコアになる形にする。

## 3. ptの流れ（確定）

1. コンテンツを遊ぶ → スコアに応じて **pt** を得る
2. ptは**主ステに100%**、**他の5ステに10%ずつ**入る（＝「その項目はそのステが上がりやすい」）
3. 1日の上限は**コンテンツごとの回数**で区切る
   （上手いほど同じ回数で多く取れる＝上達する意味が残る）。
   回数は**遊び始めた時点**で使う＝途中でやめても戻らない（引き直し封じ）
4. 累計ptからステータス値が決まる。**抽選はしない**（運動したのにINTが上がる、を起こさない）
5. ペットのLVは全ptの合計から決まる、育て具合の指標。ステの内訳とは別に持つ

> 本編のLVアップ（`rollLevelUp` の5回抽選）とは別物。ペットは確定配分。

## 4. 1日の上限（案）

全ステ **1日80pt** で揃える。神経衰弱はDEX・AGIそれぞれ80pt。

| コンテンツ | 上限 | 1回のpt（案） |
|---|---|---|
| 運動量 | 8,000歩/日で頭打ち | 1,000歩＝10pt |
| 漢字 | 20問/日（**1問＝1回**） | 正解1問＝4/5/6/8/10pt（3級〜1級） |
| 積み上げ耐久 | 5回/日 | 乗せた個数＝pt。**上限なし（青天井）** |
| 神経衰弱 | **1日1回** | 手数スコア→DEX／タイムスコア→AGI（各80pt） |
| コイントス | **1日1回** | **裏が出るまで投げ続ける。3回のうち最良の表の回数×40pt** |

リセットは他コンテンツに合わせてJST 5:00（案）。

神経衰弱は1日1回なので、**その1回の出来がそのままその日のDEX・AGIになる**。

### コイントスの当たり具合（40万回の実測）

裏が出るまで投げ続けたときの表の回数を3回ぶん取り、いちばん良い回だけを採る。

| 最良の表の回数 | 割合 | pt |
|---|---|---|
| 0回 | 12.5% | 0pt |
| 1回 | 29.7% | 40pt |
| 2回 | 24.7% | 80pt |
| 3回 | 15.5% | 120pt |
| 4回以上 | 17.6% | 160pt〜 |

期待値は表2.15回＝**約86pt**で他ステの80ptとほぼ同じ。
ただし8回に1回は0pt、まれに200pt超も出る＝LUKらしいブレの大きさになっている。

### 積み上げ耐久の当たり具合（`tools/v2-pet-stack.mjs` で実測）

上限が無いぶん、**乗せるほど「重く・速く・揺れる」の3つが同時にきつくなる**のが唯一の歯止め。
`stackGravity`（重さ）と `stackPlaceSec`（間隔）がその担当。

| 遊び方 | 平均 | 中央 | 上位1割 |
|---|---|---|---|
| 放置（何もしない） | 2.5個 | 2個 | 3個 |
| 人（反応0.30秒） | 15.6個 | 15個 | 19個 |
| 人（反応0.20秒） | 22.9個 | 23個 | 28個 |
| 遅れなしの理想操作 | 42.7個 | 42個 | 51個 |

ふつうに遊べば15個前後×5回＝おおよそ80ptで他ステと揃い、上手ければ上に伸びる。
調整するときはこの表を出し直す。

> ⚠ 青天井なので、上手い人はVITだけ他ステより伸びる（理想操作なら1日200pt超）。
> そこを詰めるなら、ptに逓減をかけるか回数を減らす。いまは**そのまま**にしてある。

## 5. 累計pt → ステータス値（案）

そのままステに変換すると1年で数万になって主人公を食う。逓減させる。

```
ステ値 = floor( sqrt(2 × 累計pt) )
```

| 累計 | ステ値 |
|---|---|
| 80pt（1日満額） | 12 |
| 2,400pt（1か月） | 69 |
| 29,200pt（1年） | 241 |

主人公への加算はさらに係数をかける（**係数は未定・要逆算**）。
v2は転職周回型で終盤の1ステが数千規模になるため、
「序盤に効きすぎず、終盤でも誤差にならない」点を tools で探る。

## 6. 現実の行動をどう取るか（確定＋注意）

**運動量＝端末の歩数センサー**。ブラウザの加速度センサーで歩数を数える。
- **https必須**（LANのhttpでは無反応。別プロジェクト「歩くRPG」で確認済み）
- **画面を開いているあいだしか数えられない**＝完全な計測にはならない

**漢字＝配当漢字リストから問題を自動生成**。
3級〜1級の配当漢字（読み・意味）を持ち、読み／書き／四字熟語の問題を組み立てる。
数千問を手入力しない。

## 7. 種族とバトル（確定・2026-08-29）

ペットは**200種**。技は4つ選んで戦う。集めて、育てて、進化させる。

| 決めたこと | 中身 |
|---|---|
| 対戦相手 | **野生のペット**（実装済み）と**他プレイヤー**（サーバー化のあと） |
| 所持 | **複数持てて入れ替え**。主人公へのステ加算は連れている1体ぶんだけ |
| バトルのステ | **種族値 × 育てたpt**。毎日の積み上げがそのまま強さになる |
| タイプ | **12＋無**の相性あり。2タイプ持ちは掛け算（4倍・1/4倍が出る） |
| LV | **ミニゲームのptで決まる今までのまま**（プレイヤーで共通） |
| 進化 | 種ごとに決まったLVで自動。2段まとめて進化することもある |

### 200種の内訳

3段進化33家系（99種）／2段進化38家系（76種）／**進化しない25種**。
進化しない種は種族値の合計が1段目の約1.6倍で、最終進化より少し低い
＝「進化しないけどそこそこ強い」。

**名前・タイプ・進化のつながりは手で決めてある**（`FAMILIES`）。
種族値と覚える技は、そこから**組み立てる**（同じ入力からは必ず同じ結果になる）。
1,200個の数字と200本の技表を手打ちすると、直すたびに破綻するため。

- 種族値＝役割（atk/mag/def/spd/bal）の配分 × 段階ごとの総量 ± idから作る小さなブレ
- 覚える技＝自分のタイプの技を**威力の低い順**に、無タイプの補助技を混ぜて並べる

### 名前の付け方（2026-08-29 に振り直し）

最初は「ヒノコリス→カエンリス→ゴウカリス」のように、
**同じ生き物語＋強くなる接頭辞**の一本調子だった。
そこで**独・露・中・伊・西・羅・希・北欧・韓・アラビア**からもじる形に変えた。

[[v2-enemy-naming]] の「**生き物の語を必ず入れる**」は残したまま、
**その語自体を外国語にする**ことで両方を立てている
（Fuchs＝フクス、волк＝ヴォルク、龍＝グイ、passer＝パセル…）。

そして**進化のたびに生き物そのものが変わる**。
「○○タヌキ」が3つ並ぶ形こそが単調の正体で、多言語にしても
「修飾語＋同じ生き物語」のままでは何も変わっていなかった。
**同じ生き物の語を家系の中で使い回さない**（テストで固定してある）：

| 家系 | 名前の流れ |
|---|---|
| 炎・物理 | フンケベルカ → ブラントフクス → インフェルレオン（独：火花の栗鼠→火災の狐→地獄の獅子） |
| 水・耐久 | シュイグイ → ハイマー → シェンロン（中：水の亀→海の馬→神の龍） |
| 草・特殊 | セメンムス → フルクレプス → メッシスケルウス（羅：種の鼠→実の兎→実りの鹿） |
| 闇・特殊 | スキアオフィス → エレボリュコス → カオスドラコン（希：影の蛇→幽冥の狼→混沌の竜） |

そのぶん生き物の語を100語ほど足してある（狼だけでも
ヴォルフ・ヴァルグ・ルプス・リュコスの4通り）。

> ⚠ **種族を id でも名前でも直に指さない**。はじめの3種を id で書いていたら
> 家系を足した瞬間に番号がずれ、名前で書き直したら今度は名前の付け替えで壊れた。
> `SPECIES.find(s => s.types[0]==='炎' && s.stages===3 && s.stage===0)` のように
> **条件で選ぶ**のがいちばん保つ。

### モチーフの生き物（開発用）

 に、種ごとの**元ネタの生き物と言語**を持たせてある
（フンケベルカ＝リス／露 белка、シェンロン＝リュウ／中 神龍…）。
**プレイヤーには出さない**。名前を足すときに「この家系はもう狼を使った」が
一目で分かるようにするための控えで、テストが
「全200種にモチーフがある」「家系の中でモチーフが重ならない」を見張っている。

### 技の名前

⚠ **よそのゲームの技名をそのまま使わない**（2026-08-29 ユーザー指摘）。
最初「たいあたり」「かえんほうしゃ」のように他所の名前をそのまま置いていた。
全78技を名前も威力も作り直してある（火種／業火吹き／獄炎／紅蓮突撃…）。
足すときは、思いついた名前が他所のものでないか必ず確かめること。

### LVが共通なことの意味

新しく仲間にした子も**すぐ同じLVで戦える**。育て直しの苦行がない代わりに、
進化LVに届いていれば仲間にした瞬間に進化する。種ごとの差は**種族値と覚える技**で出る。

## 8. 作りながら分かったこと

**積み上げ耐久は「倒れる力」が要る。**
最初は傾きにランダムな揺れを足すだけにしていたが、それだと戻す力も倒れる力も無い
ただのランダムウォークで、放置の平均が25個（＝上限16個を素通り）になった。
**何もしないほうが成績が良い**ミニゲームになっていた。
傾くほど倒れが速くなる（倒立振子）形にして解決。`stackGravity`。

**積み上げは上限を置かず、難易度で止める。**
一度は16個で打ち切る形にしたが、**青天井にして代わりに難易度を上げ続ける**方針に変更
（2026-08-27 ユーザー指示）。重さ・間隔・揺れの3つが積むほどきつくなるので、
実質の天井は腕前で決まる。上限を書き足したくなったら、まず `stackGravity` を疑うこと。

**回数は「遊び始めた時点」で使う。**
終わったときに数えていたら、出だしが悪ければ抜けて引き直せた（神経衰弱を1手めくって
戻っても「あと5回」のまま）。回数で区切った意味も、「上手いほど多く取れる」も消える。
`beginPlay`（回数を使う）と `scorePlay`（ptを足す）に分けてある。
途中でやめたら1回は戻らない。画面にもその旨を出す。

**こぼれる10%は端数を繰り越す。**
1プレイごとに切り捨てていたら、コイントス（1回8pt）は 8×10%＝0.8 が毎回0になり、
**他の5ステが永久に0のまま**だった（10回投げてLUK+40・他は全部0）。
`spread` が `carry` を返し、次のプレイへ持ち越す。
直したあと：コイン10回でLUK+32・他ステ+3ずつ・端数0.2が残る。

**強い技ほど後のLVで覚えさせる。**
技を順番に並べるだけだと、自タイプの弱い技が少ない種（炎の物理技は2つしかない）で
**威力120の技をLV5で覚えて**しまった。覚えるLVは技の威力から決める。

**種族のidを画面に直に書かない。**
はじめの3種を id で指定していたら、家系を足したときに番号がずれて
**炎・水・草のつもりが全部炎**になった。名前で引くこと。

**漢字は語数だけでは実力にならない。**
ただの抽選で出していると、覚えた語も知らない語も同じ確率で出て、
**苦手がいつまでも苦手のまま残る**。そこで語ごとに正解数・不正解数を持ち、
**間違えた語ほど濃く、正解を重ねた語ほど薄く**出す（`kanjiWeightOf`）。

| その語の状態 | 出やすさ |
|---|---|
| 間違えたほうが多い（苦手） | 12 |
| まだ一度も出していない | 6 |
| 正解と不正解が同数 | 6 |
| 正解が1回多い | 3 |
| 正解が2回多い | 2 |
| 正解が3回以上多い（覚えた） | 1 |

覚えた語も「1」で残す＝忘れたころにまた出る。直近6語は続けて出さない。
記録は `localStorage['v2:petKanji']`（ptとは別。勉強の記録なので分けてある）。

**1日20問を超えても練習だけは続けられる。**
上限は「ptが入る量」の上限であって、勉強の上限ではない。
使い切ったあとは練習モードに切り替わり、何問でも解ける（ptは入らない・
覚え具合の記録は残る）。ここを塞ぐと「もっと勉強したい」が止まってしまう。

**級の倍率は「1問ぶんを切り捨てても差が残る」ように刻む。**
準2級の倍率を1.1にしていたら、4×1.1＝4.4→切り捨て4で3級とまったく同額になり、
上の級を選ぶ意味が消えていた。ゲームが実際に配るのは1問ぶんなので、
テストも1問で見る。いまは 4/5/6/8/10pt。
（こぼれる10%の端数と**同じ形の穴**。1回ぶんが小さい値を切り捨てると差が死ぬ）

**dtは負にしない。**
`Math.pow(STACK_DAMP, dt)` は dt が負だと減衰ではなく増幅になり、
たった1フレームで傾きが振り切れる。rAFのタイムスタンプが `last` より手前に
来ると実際に起きる。lib側と画面側の両方で下限0を守っている。

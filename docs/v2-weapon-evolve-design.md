# バトルフロンティアⅡ — 武器の進化（戦闘記憶）

2026-08-20 実装。シャングリラ・フロンティアの武器進化を下敷きにしたユーザー提案。

> 武器の熟練度が一定以上になったら、これまでの戦闘記憶によってその人だけの能力が付与される
> （2026-08-20 追加）能力は100〜200種類ぐらい、もっと細分化して、バランスが壊れないぐらいの能力に。
> 例：クリティカル攻撃が意図的に多い場合 → 「クリティカル時、HPが1%減るが与えるダメージ+20%」

## 決めたこと

| 論点 | 決定 |
|---|---|
| ルーンの刻印との関係 | **別枠**。ソケットを食わない |
| 進化の回数 | **段階的に複数回**（節目ごとに1つ増える） |
| 付く能力の決まり方 | **戦績から自動で決まる**（候補から選ばせない） |
| 能力の数 | **163種**。得1〜2個＋代償0〜1個の組み合わせ |

ルーン＝運で集める／進化＝使い込んで得る、と役割を分けている。
ルーンの特殊能力56種は何度引いても同じ表から出るだけで、プレイの履歴を一切見ていない。
進化は**記録の偏り**だけが入力になる＝同じ武器でも人によって別物になる。

## 熟練度

- 貯まるのは**装備している武器だけ**（右手・左手にそれぞれ独立して貯まる）
- 防具・アクセには貯まらない（「この1本を使い込む」話なので、対象を増やすと薄まる）
- 出撃・アリーナの**どちらで戦っても**1戦につき1

| 段階 | 熟練度 | 値の予算 |
|---|---|---|
| 1つ目 | 100戦 | 6% |
| 2つ目 | 500戦 | 10% |
| 3つ目 | 2000戦 | 15% |

## 何が付くか

```
能力の点数 ＝ 軸の強さ × （0.5 ＋ 0.5 × 部品の噛み合い） × 同じ軸なら0.75
```

- **噛み合い**＝その能力の部品が指す**別の軸**がどれだけ立っているか。
  クリティカル型でも「瀕死で勝ちがち」な人と「被弾が多い」人で別の能力が付く。
- ★噛み合いを見るとき**その能力自身の軸に属する部品は数えない**（中立の0.5で置く）。
  数えると「クリティカル率+%」のような素直な能力が常に最強になり、2つめの偏りが死ぬ。
- 同じ能力は2回付かない。2つめ以降は同じ軸に0.75を掛けて系統を散らす。
- 軸ごとに最低戦闘数（当てた回数50／勝ち20／戦闘30）があり、それ未満なら何も付かない。

付く値 ＝ **段階の予算 × 軸の強さ × 部品ごとの倍率(w)**、最低0.1%。

⚠**「その軸が立つ人にとってはほぼ無条件になる」条件に高い倍率を付けない**
（2000戦×4型のシミュレーションで判明）。速攻型は3手で決着する＝「最初の3回の行動」は
ほぼ常時／物理型は物理しか撃たない／長期戦型は6手目以降が本番。0.6〜2.1 に抑えてある。

### 代償つきの能力

ユーザーの例そのままの形。代償を背負うものほど得の倍率が大きい＝**噛み合う人にだけ強い**。

- 紅蓮の一閃 … クリティカルの与ダメージ+45%／クリティカル時に最大HPの2.7%を失う
- 一点集中 … クリティカル率+24%／命中率-13.5%
- 背水 … HP30%以下のとき与ダメージ+51%／被ダメージ+15%
- 薄紙の構え … 回避率+19.5%／VIT-12%

得と代償の釣り合いは、部品ごとの**換算値（unit）**を掛けた重さで比べる。
毎ターン積み上がる部品（回復・吸収）は同じ1%でも重いので、換算値が大きい。

## 保存と不正対策

戦闘そのものはクライアントが回すので、戦績もクライアントから送られてくる。

- `v2_weapon_record(p_ids, p_rec)` … **1戦あたりの増分を頭打ちにして**積む
  - 戦った回数は必ず+1、勝ちは最大1、クリはヒット数まで、回避は被弾数まで…と全項目に上限
  - 倒した敵は1戦に1体だけ。勝っていなければ数えない
  - 積むのは**自分のもので、部位が武器のもの**だけ
- `v2_weapon_evolve(p_id, p_key, p_s, p_foe)` … **効果の値はサーバーが作り直す**
  - クライアントが送るのは「どの能力か」と「偏りの強さ(0〜1)」だけ。値は送れない
  - サーバーは `v2_evolve_traits`（JSから生成した名簿）の倍率で計算する
  - 段階・熟練度・重複・宿敵の名前もサーバーが検証する

⚠ 戦闘をサーバー権威化するときは、この検証ごと本物の計算へ差し替えること。

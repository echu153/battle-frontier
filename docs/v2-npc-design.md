# バトルフロンティアⅡ — 自動成長NPC（アリーナの住人）

2026-08-27 実装。**人が少なくてもアリーナが成り立つ**ようにするための、勝手に強くなって
勝手に挑戦してくる疑似プレイヤー100体。

## 決めごと（2026-08-27 ユーザー決定）

| 論点 | 決定 |
| --- | --- |
| 動かす場所 | **Edge Function（v2-npc-tick）＋ pg_cron**。誰も遊んでいない時間帯でも動く。アリーナの勝敗は**本物の runBattle** |
| 成長のやり方 | **数字で育てる**。出撃の戦闘は回さない。「1時間あたり何EXP」だけを持つ |
| 強さの上限 | アリーナ最上階の目安（`powerOfFloor(50)` ≒ 29,749）で頭打ち。**一旦これで、後で調整する** |
| 見え方 | **NPCだと分かるようにする**（名前の横に `NPC` の印） |
| 展開の仕方 | **開発中は6体だけ動かし、v2の一般公開と同時に残り94体を一斉に起こす**（2026-08-27 追加指示） |

## 成長を「計算で出せる」理由

v2の成長は LVアップ1回＝5回抽選・転職1回＝転職回数×100戦闘力の配り直しで、
**どのステに当たっても戦闘力の増えぶんは同じ**（`stats.js` の `unit` がその換算）。つまり

```
戦闘力 = 39 ＋ 転職回数×100 ＋ (LV-1)×5
```

が乱数によらず決まる。乱数で変わるのは**8種への散らばり方だけ**なので、
`seed` を決めておけば通算EXPから今の姿を毎回同じように作り直せる。
＝ **DBに持つのは `total_exp` ひとつだけ**でよい（ステもスキル編成も毎回作り直す）。

⚠ 転職するとステは初期値へ戻る。LV100ぶんの +495 が消えて転職ぶんの +100 が乗るので、
戦闘力は**のこぎり刃**に伸びる（転職の直後は一時的に弱くなる）。プレイヤーとまったく同じ形。

## 100体の顔ぶれ

- **職業** … 上位職20職を順に（1職5体）。NPCは**ずっと同じ職業**に転職し続けるので、
  転職回数で伸びる職業補正もそのまま効く＝職業ごとの色が出る
- **成長速度** … 15〜600 EXP/時を log で等分（40倍の幅・遅い人のほうが多い）。
  参考：手で出撃を回し続けるプレイヤーはおよそ 3,420 EXP/時
- **いまの強さ** … 1階〜50階の目安に散らす（作った瞬間から一覧が埋まっている）。
  「その強さになるまでに速度ぶんの時間がかかった」として `born_at` を逆算する
- **装備** … 実物は持たせない。素の戦闘力に対する割合（25%→最大120%・転職回数で伸びる）として数字で乗せる。
  ＝ ランキング・取引所・図鑑・デイリーには一切出てこない

## アリーナでの動き

プレイヤーとまったく同じ規則で動く（`arena.js` の天空闘技場方式）。

- 挑戦の間隔は速い人ほど短い（20〜240分・±30%）
- 勝てばその階の階層守護者になる。守っているあいだは挑戦できない
- 負ければ1つ下の階へ
- **席を降りる**のは「その階には強すぎる（2階ぶん上の目安に届いた）」か「5連勝した」とき。
  席が回らなくなるのを防ぐための仕組み

## 開発中と一般公開

100体すべてを最初からDBに入れておくが、**動くのは `active = true` のものだけ**。

- **開発中** … 6体（`npc.js` の `DEV_ACTIVE_IDS` ＝ 1・51／2・52／6・56）。
  **1階・2階・6階**に「ゆっくり守る側」と「速い挑む側」を1体ずつ置いてある。
  開発キャラが実際に当たれる場所で、席の奪い合いと「強くなりすぎて席を降りて上へ行く」
  動きが必ず見られるようにするため。残り94体は `active = false` で眠っていて、
  成長もしないし挑戦もしてこない
- **一般公開と同時** … `supabase_v2_npc_deploy_all.sql` を1本流すと残り94体が起きる。
  眠っていた47体ぶんの席も、そのとき空いている階にだけ入る（プレイヤーの席は奪わない）

⚠ 起こすときに `last_tick_at` を `now()` へ直すのが肝。直さないと
「眠っていた期間 × 速度」ぶんの成長が**まとめて1回で入って**、全員が一気に最上階の強さになる。
Edge Function 側にも1週間ぶんで頭を打つ保険（`MAX_CATCHUP_HOURS`）を入れてある。

## 運用

```
① supabase_v2_core.sql（全文）
② supabase_v2_npc_seed.sql       ← 100体を入れる（動くのは6体）
③ supabase_v2_npc_cron.sql
④ supabase_v2_npc_deploy_all.sql ← v2の一般公開と同時に
```

Edge Function のデプロイ：

```
node tools/v2-npc-fn-sync.mjs
supabase functions deploy v2-npc-tick
supabase secrets set CRON_SECRET=＜秘密の文字列＞
```

止めたいとき：

- `select cron.unschedule('v2-npc-tick');` … 全部止める
- `update public.v2_npcs set active = false;` … NPCだけ止める
- `update public.v2_npcs set active = false where id = 7;` … 1体だけ止める

## 調整するとき

- 強さの上限 … `npc.js` の `POWER_CAP`
- 成長速度の幅 … `npc.js` の `SPEED_MIN` / `SPEED_MAX`
- 装備の強さ … `npc.js` の `GEAR_RATIO_*`
- 挑戦の頻度 … `npc.js` の `ARENA_MIN_MINUTES` / `ARENA_MAX_MINUTES`
- 開発中に動かす顔ぶれ … `npc.js` の `DEV_ACTIVE_IDS`

直したら `node tools/v2-npc-curve.mjs` で伸び方を見て、
`node tools/v2-npc-seed.mjs` と `node tools/v2-npc-fn-sync.mjs` を流し直す。
**勘で数字を置かないこと。**
